# 布局回归脚本

## 放在哪、怎么跑
1. 把 `regress.js`、`render.js`、`baseline.json` 放进项目文件夹，和 `core.js`、`data.json` 同一层。
2. 在这个文件夹里运行：`node regress.js`
3. 看最后一行：
   - 「通过」＝没有指标变差，可以继续。
   - 「变差（必须修）」＝列出场景名和数字，先修再继续。

## 两种用法
- **改了排版、想确认没变差**：`node regress.js`。
- **纯重构、不应该有任何视觉变化**：`node regress.js --strict`。它会比较每个场景的“布局指纹”（所有卡片、圆点、图标、线条的位置和文字），只要有一个场景有半个像素的变化就判失败。

## 它检查什么（共 1612 个场景）
- 10 个命名场景：你截图里的 7 个情形，加上 3 个极端情形（司马炎三位夫人的家族块全开、13 个孩子全展开、卫玠两位夫人）。
- 178 个人 × 多种操作 × 两种“归并生母不详”设置（开、关）：默认、往上展开、展开子女与配偶、双击一个家族、双击全部家族。
- **语义不变量**：画面上每个“+N”小圆点（往上展开、展开子女共 801 个，两种归并设置都查），显示的 N 必须等于点开后真正多出来的人数。
- **状态分层不变量**：
  - 纯度：同一份意图重复渲染、中间穿插渲染别人的画面，结果必须完全相同；`buildView` 不得修改意图（45 个样本）。
  - 块的左右稳定：依次双击几个家族、中间展开别处的子女和配偶，已经定下的块不许翻边（46 条序列；脚本里还会对照“不记忆”的情况，现在是 10 次会翻边，记忆之后是 0 次）。

| 指标 | 含义 | 变多/不一致时 |
|---|---|---|
| 卡片重叠 | 同一行两张卡片叠在一起 | 判失败 |
| 重复卡片 | 同一个人出现两张卡 | 判失败 |
| 悬空线端点 | 线的端点没有接到卡片、圆点、图标或别的线 | 判失败 |
| 线穿卡片 | 线穿过卡片内部 | 判失败 |
| +N 不一致 | 小圆点上的数字和实际展开人数不一致 | 判失败 |
| 同一意图结果不同 / 意图被修改 / 块翻边 | 状态分层不变量被破坏 | 判失败 |
| 线线交叉 | 横线竖线垂直相交（规则允许，仅记录） | 只提醒 |
| 画面宽度 | 整个画面的宽度 | 超过基线 5% 加 20px 时提醒 |

## 当前基线记录了什么（现状，不是目标）

- 重复卡片 152 张，涉及 50 个场景：原因还没查明，要单独排查。
- 线线交叉 43（仅记录）。

## 其他命令
- `node regress.js --update`：用当前结果覆盖基线。只在确认“变好了”之后用。
- `node regress.js --svg out/`：把 10 个命名场景存成 SVG，用来肉眼复查。
- `node regress.js --only A_`：只跑名字以 `A_` 开头的场景（这时不跑 +N 检查）。
- `CORE=./旧版core.js node regress.js`：拿另一个版本的 core.js 来对比。

## 注意
- 基线和 `data.json` 绑定。数据改了（增删人物、改关系），先用 `--update` 重新生成基线。
- 场景用人物姓名查找；改名后脚本会报“找不到人物”。
